token 主要花在「重复读上下文」上；书和代码本身只占小头（估算）

对话记录里没有 token 计数，所以这里是估算模型。拖动滑块改假设，柱子和总数会跟着变。实测的只有字数、字节数和截图数。

估算公式与依据
  • 读书 = 704,278 字（实测：jig-atp-book.txt 字符数）× 读入比例 × 每字 token 数
  • 写出 = 456,217 字节（实测：19 个主题的 scene.js + steps.js 共 290,989 B；ATP 试点 66,958 B；饮食与维生素页 31,904 B；引擎与脚本 66,366 B）÷ 3 字节/token × 改写倍数
  • 看截图 = 截图张数 × 每张 1,200 token（假设）。实测：jig-site 下保存了 174 张 shots 截图，今天的审计又生成 244 张
  • 上下文重复 = 工具调用轮数 × 平均上下文长度。两者都是假设值，没有记录可查

问题 3 · 问题与解决

手机上标签出界：拉远镜头不够，要逐个把标签挪回画面

拖动下面的滑块，把屏幕变窄。three.js 的竖直视角固定，所以屏幕变窄只会把两边裁掉；而标签是固定像素大小的网页文字，镜头拉远后物体变小，标签却不变小。三个按钮对应三种做法。

层次内容
要求每个可见标签完全落在 3D 舞台内，任意两个标签不重叠，也不压住「复位视角」按钮（audit.js 的判定）。
心智模型标签是贴在窗户上的固定大小便利贴：窗户变窄，便利贴不会变小，只能挪位置。
教学模型Fig. 8 的模拟：按真实锚点坐标、镜头距离和 45° 视角投影，标签宽度按字数估算（示意）。
真实实现fitLabels()：每帧在 CSS2D 定位后执行；按「高亮 → 普通 → 淡化」排序，先夹回舞台，再在附近偏移网格里找最近的空位；用位置签名缓存结果；手机上标签可换行、淡化标签只留中文。

现状：这项修复已在 11 月 12 日 21:45（台北时间）推到线上仓库（提交 eb92a86「Mobile label layout: clamp labels into stage, de-overlap, horizontal BV chart on phones」），改动了 19 个主题的 lib.js 与 style.css；蛋白质消化第 6 步的柱状图在手机上改成了横向。线上复测由负责修复的任务进行，本页没有重复验证。

要记住的

四条可以带走的经验

  1. 内容和几何分开。steps.js 只放数据，引擎负责镜头、高亮和标签，所以加主题主要是写内容。
  2. 结构图用代码画。生成式图片只做氛围图；分子、蛋白、反应式要用 SVG 或 RDKit 坐标保证正确。
  3. 窄屏问题要在屏幕坐标里解决。拉远镜头只会让物体变小，固定像素的标签必须逐个夹回舞台并避让。
  4. 自动审计是主要成本，也是质量来源。366 个画面的批量检查把「肉眼看截图」变成可重复的 0/1 判断。

想自己验证：打开 /workspace/jig-site/_tpl/lib.js 的 go() 与 camTarget()，再对照任一主题的 content/steps.js；运行 node audit.js <网址> out.json 可复现 Fig. 9 的数字。
